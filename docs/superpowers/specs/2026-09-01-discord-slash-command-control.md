# Discord Slash Commands 控制台设计

历史设计与实现记录：本文属于现名“码驿 · CodexRelay”的项目，保留当时的目录、服务标识、界面名称和示例。当前安装与更新请看[入门指南](../../GETTING-STARTED.md)，更名时保留的兼容标识见 [README](../../../README.md#兼容标识)。

## 背景与目标

现有 `discord-bridge.mjs` 已经承担三类 Discord 通知、任务通知映射、自由回复续接、忙碌任务排队和 Codex 完成事件补发。新增能力是在同一个私有 Bot 中提供原生 Discord Slash Commands，让唯一授权用户可以从手机查询主任务、查看完整结果、搜索历史、新建或继续指定任务、管理继续队列、查询周额度并检查系统状态。

本次扩展不建立公网 HTTP 服务，不新建第二个后台进程，也不改变三类通知的频道和分类规则。现有“回复一条任务通知即可继续原任务”的方式继续保留。任务通知标题简化为固定的 `Codex 任务已完成` 或 `Codex 任务待确认`，不再在标题后重复拼接任务名；项目名、任务名、任务和结果仍完整显示在消息内部。

## 已确认约束

- 使用 Discord 原生 Slash Commands，不使用文本前缀命令。
- 所有命令回复、分页、按钮回执和错误信息均为仅调用者可见的私密消息。
- 只允许配置中的服务器和唯一授权用户操作；所有交互在执行前重新校验身份。
- 任务查询和续接只包含 Codex 侧边栏主任务，不包含子智能体、后台回合、心跳或内部任务。
- 完整任务内容按需从本机 rollout 读取；持久化索引只保存元数据和文件定位信息，不复制完整对话。
- `/继续任务` 必须先选择目标任务，再打开私密多行输入框。
- `/新建任务` 只能选择 App Server 返回的已保存项目或“无项目”，不接受手工目录路径。
- Git 项目自动使用隔离工作树；非 Git 项目直接使用已保存项目目录。
- 无项目任务统一使用可配置目录，默认 `%USERPROFILE%\Documents\Codex\Discord Tasks`。
- 电脑关机期间命令不可执行；Discord 会明确显示 Bot 离线。已有队列在下一次登录启动后继续处理。
- 新增的命令配置、交互、日志和状态文件不保存或输出 Bot Token、Webhook 地址或其他凭据；现有 `legacyDiscordWebhooks` 不参与本功能，也不得被读取到回复或日志中。

## 架构选择

### 选择：扩展现有单进程桥接

`discord-bridge.mjs` 继续作为进程入口和生命周期管理器，并增加 Discord Gateway 连接。具体能力拆成独立模块，由入口组合：

1. **Gateway 连接器**：接收 `INTERACTION_CREATE`，处理心跳、重连和会话恢复。
2. **命令注册器**：启动时幂等同步当前私有服务器的 10 个 Guild Commands。
3. **交互路由器**：统一完成鉴权、3 秒内响应或私密延迟响应、命令分发、按钮和 Modal 回调。
4. **任务索引器**：从 Codex sessions 和侧边栏元数据构建主任务索引，并按需读取完整任务与结果。
5. **任务创建器**：通过 App Server `project/list`、`thread/start` 和 `turn/start` 创建持久主任务；Git 项目先建立隔离工作树。
6. **任务续接器**：复用现有 `resumeCodexThread` 和 pending queue，支持 Slash Command 与通知回复两种来源。
7. **状态与额度读取器**：只读现有桥接状态、通知日志摘要和 `quota-state.json`，不复制额度算法。

模块拆分避免继续扩大 `discord-bridge.mjs`；入口只负责启动、停止和组件编排。现有 REST 轮询回复、rollout 完成补发和通知去重保持不变，降低迁移风险。

### 不采用的方案

- **公网 Interaction Webhook**：需要公网域名、TLS、签名校验和额外服务，不符合本机私密部署目标。
- **独立 Slash Command 服务进程**：隔离更强，但会重复加载 Token、索引和队列，并增加计划任务与单实例协调成本。

## Discord 接入与生命周期

- 命令使用 Guild Commands 注册，修改后立即在当前私有服务器生效，不等待全局命令传播。
- Gateway 连接只申请交互所需 intent；现有频道历史轮询暂不迁移，避免改变已验证的离线补收行为。
- 普通查询如果可能超过 3 秒，先发送私密 deferred response，再编辑原回复。
- `/继续任务` 在收到命令后直接返回 Modal；Modal 提交后再执行续接或入队。
- `/新建任务` 在项目自动补全后直接返回 Modal；Modal 提交使用 Interaction ID 做持久幂等键，避免 Discord 重试重复创建任务或工作树。
- 每个 Interaction ID 只处理一次。重连后收到重复事件时返回已有结果或安全忽略，不重复续接任务。
- Gateway 断线使用 Discord 推荐的退避和 Resume；无法恢复时重新 Identify，Slash Command 不影响本地完成通知监听。

## 命令设计

### `/任务列表`

显示最近 10 个侧边栏主任务，默认按最后活动时间倒序。可选状态：`全部`、`运行中`、`待确认`、`已完成`、`失败`。每项显示项目名、任务名、状态、开始时间或最后活动时间、累计运行时间，并提供“查看详情”按钮。

### `/任务详情`

必填参数 `任务` 使用自动补全，候选项显示项目名、任务名和当前状态，值为稳定的 `threadId`。详情包含项目名、任务名、状态、任务 ID 后八位、开始时间、最后活动时间、运行时间、原始任务和最新结果。超过 Discord 单条限制时私密分页，不直接截断；提供上一页、下一页和“继续任务”按钮。

### `/任务搜索`

必填参数 `关键词`。匹配项目名、任务名、用户任务文本和助手结果，默认返回最近且相关度最高的 10 个主任务。结果只显示安全摘要，并通过“查看详情”按钮按需读取全文。空关键词或只含空白字符不执行扫描。

### `/新建任务`

必填参数 `项目` 使用 App Server `project/list` 自动补全，候选项为当前 Codex 已保存项目，并额外提供“无项目”。选择后打开仅调用者可见的多行 Modal，任务内容最少 1 个、最多 4,000 个字符；任务名由 Codex 根据首条任务内容自动生成。

提交后重新读取项目并校验 `projectId`，不能使用过期候选或手工构造路径。对于多根目录项目，第一根目录决定运行位置；非 Git 项目将全部有效根目录作为 `runtimeWorkspaceRoots`，Git 项目则用新工作树路径替换第一根目录，并保留其余有效根目录。

运行位置按以下规则自动确定：

- Git 项目：从远端默认分支创建 `codex/discord-<时间>-<随机串>` 分支和隔离工作树；没有远端默认分支时以当前 `HEAD` 为基准。工作树根目录默认 `%CODEX_HOME%\worktrees\discord`，可通过 `discordWorktreeRoot` 修改。
- 非 Git 项目：直接使用保存项目的第一根目录。
- 无项目：使用 `discordProjectlessRoot`；默认 `%USERPROFILE%\Documents\Codex\Discord Tasks`，不存在时自动创建。

工作目录准备成功后，通过同一 App Server 连接依次调用 `thread/start` 与 `turn/start`。`thread/start` 使用 `ephemeral: false`，保存 `projectId`、`cwd` 与全部运行时工作区根；无项目任务显式使用 `projectId: null`。`turn/start` 发送 Modal 中的原始任务文本。成功回执显示项目名、当前可用的任务名或“生成中”、任务 ID 后八位、运行方式和运行目录的安全摘要；异步标题生成完成后更新任务索引。

任务创建成功后不自动删除隔离工作树，因为任务可能继续接收 `/继续任务`。若工作树创建后、`thread/start` 之前失败，只清理由本次操作新建的工作树和分支；若线程已经创建但 `turn/start` 失败，则保留线程与工作树并返回任务 ID，便于之后继续处理。

### `/继续任务`

必填参数 `任务` 使用与 `/任务详情` 相同的自动补全。选择后打开仅调用者可见的多行 Modal，用户输入的内容原样作为新的 Codex 用户消息发送给指定主任务。

如果原任务可恢复，立即调用现有 App Server 续接；如果任务正被桌面端占用，则写入继续队列并返回队列编号。恢复失败时不创建新任务。Modal 重复提交或 Discord 重试不会产生重复 Codex turn。

### `/继续队列`

列出等待发送的继续请求，包括队列编号、目标项目与任务、内容摘要、来源、加入时间、最后尝试时间和状态。每条尚未开始的请求提供“取消发送”按钮。取消采用原子更新；已经开始或已经送达的条目不能撤销，并明确返回当前状态。

现有“回复任务通知”产生的排队项和 `/继续任务` 产生的排队项统一显示和重试。

### `/额度`

读取最近一次本机官方 Codex 周额度快照和现有追踪状态，显示：

- 当前周额度剩余百分比；
- 最近一次额度变化及距今时间；
- 本次使用速度比上次更快或更慢；
- 距下次重置的时间；
- 按当前速度连续使用的预计耗尽时间；
- 按本次重置以来平均速度的预计耗尽时间；
- 快照采集时间和数据新鲜度。

手动查询不会伪造刷新，也不会调用未公开的额度接口。Codex 尚未产生新快照时，显示最后已知数据并明确标注采集时间。

### `/系统状态`

显示 Bot Gateway、Discord REST、通知监听、rollout 完成补发、任务索引、继续队列和额度监控的状态，附最近成功时间、最近错误摘要和当前排队数量。输出必须脱敏，不显示 Token、完整路径中的敏感用户名、完整用户输入或 Webhook 地址。

### `/系统测试`

可选枚举参数 `类型`，省略时使用 `快速`，并提供：

- `快速`：默认选项。不向频道发送消息，只检查 Bot Token 可解密、Gateway 在线、Discord REST 可用、三个频道存在且具备所需权限、任务索引可读、继续队列状态可读、临时原子写探针成功、额度状态可解析以及完成监听仍在推进。写探针只使用临时文件，不修改真实队列。
- `完整`：先执行快速检查，再通过正式出站发送链路向“任务完成”“任务待确认”“额度变化”三个频道各发送一条明确标注的测试通知，汇报每条成功或失败及耗时。

完整测试通知不写入任务消息映射，不能通过回复测试消息续接任务；测试不会创建 Codex 任务、启动 Codex turn、消耗额度或修改额度变化历史。只有实际测试通知本身会出现在三个频道。

### `/帮助`

显示全部命令、参数、常用示例、隐私说明以及“电脑离线时命令不可执行”的提示。

## 任务索引与详情读取

任务索引只持久化以下字段：`threadId`、项目 ID、项目名、任务名、状态、创建与最后活动时间、运行时间、rollout 文件路径、最近已知偏移、是否为侧边栏主任务，以及由 Discord 创建时的工作树路径与分支名。完整用户输入与助手结果不进入索引文件。

启动时扫描现有 sessions 重建或校正索引，之后复用 rollout 监听增量更新。主任务资格沿用 `dispatcher.ps1` 已验证的侧边栏与 session metadata 判定，避免 Slash Commands 与通知产生两套不同规则。

任务正文搜索使用只存在于进程内的惰性文本缓存；缓存按 rollout 路径与偏移失效，进程退出即消失，不把完整对话另存到磁盘。首次搜索可以使用私密延迟响应，避免为了追求即时返回而截断扫描范围。

任务详情按 `threadId` 定位 rollout，从事件中提取原始用户任务、最新助手最终结果和时间信息。文件已被清理或内容不完整时仍返回索引元数据，并明确说明哪些正文不可用。

运行时间优先使用 turn/session 时间戳计算：已完成任务显示开始至最终完成；运行中任务显示开始至当前时间。缺少可靠时间戳时显示“未知”，不使用文件修改时间冒充精确运行时间。

## 私密交互、分页与按钮

- 所有 command response、autocomplete 之外的回执、分页和错误均带 Ephemeral 标志。
- 自动补全最多返回 Discord 允许的 25 项；优先最近活动和名称匹配。
- 分页状态使用短期随机 ID 保存，不把完整路径、用户输入或可伪造的 thread 参数直接放入 `custom_id`。
- 按钮和 Modal 回调再次验证服务器、用户、过期时间和目标任务。
- 长正文按段落边界分页；代码块无法完整放入一页时安全闭合并在下一页重新打开，避免破坏 Discord Markdown。
- 临时分页状态到期后，按钮返回“内容已过期，请重新执行命令”，不会猜测目标任务。

## 数据与状态文件

- 新增 `discord-task-index.json`：主任务元数据、rollout 定位、项目 ID 和由 Discord 创建的工作树元数据，原子写入，可在损坏或删除后从 sessions 与 Git 工作树信息重建。
- 扩展 `discord-inbox-state.json`：统一保存通知回复和 Slash Modal 产生的继续队列、重试状态、Interaction 去重记录，以及 `/新建任务` Interaction 到已创建 thread ID 的幂等结果。
- 可新增轻量运行时状态文件记录 Gateway 会话、最近心跳和组件健康时间；不得持久化 Interaction Token。
- `quota-state.json` 继续作为额度查询来源。
- `discord-message-map.json` 继续只负责任务通知回复映射。

状态文件损坏时先保存带时间戳的备份。可重建的索引从 sessions 重建；不可安全恢复的待发送队列不自动猜测或重新创建，并在 `/系统状态` 中告警。

## 安全边界

- 每个命令、按钮、Modal 和自动补全都校验 Guild ID 与授权用户 ID。
- 只允许读取已判定为侧边栏主任务的 `threadId`；不能通过手工构造参数读取任意 session 文件。
- `/新建任务` 只接受 `project/list` 返回的项目 ID 或固定的“无项目”值；不得把 Discord 文本解释为本机路径、Git ref 或 Shell 参数。
- `/继续任务` 只能恢复已存在的主任务；本功能不提供停止任务、重试失败任务、执行任意本机命令或切换用户。
- 工作树分支名由程序生成并固定使用 `codex/discord-` 前缀；所有 Git 参数作为独立进程参数传递，不拼接 Shell 命令。
- Discord mentions 在通知和交互输出中全部禁用；用户内容作为 Codex 文本传递，不拼接进 Shell 命令。
- 日志仅保留事件 ID、任务 ID 后八位、组件状态、错误类别和耗时，不记录完整命令正文或 Bot Token。

## 错误处理

- 未授权用户或错误服务器：返回私密拒绝，不泄露可用任务或系统信息。
- Discord 429：遵守 `retry_after`，查询命令返回可重试提示，续接请求保留幂等状态。
- Gateway 断线：后台重连；通知完成监听和已有队列重试继续运行。
- 任务索引尚未完成：查询返回“索引构建中”与进度，不使用不完整结果冒充完整列表。
- 任务 rollout 已不存在：详情只返回可用元数据并标注正文不可读取。
- 项目在候选选择后被删除或根目录失效：不创建任务，提示重新执行 `/新建任务`。
- Git 状态或默认分支无法解析：不创建工作树或线程，返回脱敏错误；不回退到直接修改项目目录。
- 工作树已创建但线程尚未创建时失败：只删除本次操作创建的工作树和临时分支。
- `thread/start` 成功而 `turn/start` 失败：保留持久线程和工作树，返回任务 ID，不自动再次发送首条任务。
- Codex active writer：续接进入统一队列，每 30 秒按现有机制重试。
- Codex 恢复失败：标记失败，不新建任务；用户可从详情重新发起新的继续请求。
- 完整系统测试某一路失败：其他两路继续测试，最终给出逐项结果，不因单项失败隐藏其余状态。

### 现场验收

1. 十个中文 Slash Commands 在私有服务器可见，其他用户无法获取任务信息。
2. 所有命令结果和按钮回执只有授权用户可见。
3. 最近任务、详情全文、关键词搜索和运行时间与 Codex 侧边栏主任务一致，子智能体不出现。
4. `/新建任务` 能从已保存项目或“无项目”创建持久主任务；Git 项目使用隔离工作树，非 Git 项目使用保存目录，重复提交不重复创建。
5. `/继续任务` 可以立即续接空闲任务，也能对繁忙任务入队；`/继续队列` 能安全取消尚未开始的项。
6. `/额度` 与本机最新官方额度快照一致，并显示快照时间。
7. `/系统测试 类型:快速` 不产生频道消息；`类型:完整` 只产生三条标注清楚且不可回复续接的测试通知。
8. 任务完成和待确认通知标题不再重复任务名，消息内部仍保留项目名、任务名、任务和结果。
9. Bot、Codex 或 CC Switch 重启后命令自动恢复，索引可重建，队列和新建任务不重复执行。

## 明确不在本次范围

- 公网 Interaction Webhook 或云端常驻服务。
- 多用户、多服务器或角色权限系统。
- 停止、强制终止或自动重试 Codex 任务。
- 自动删除已成功创建任务所使用的 Git 工作树或分支。
- 在 Discord 中修改通知分类规则或额度算法。
- 电脑关机时远程唤醒或继续执行 Codex。
