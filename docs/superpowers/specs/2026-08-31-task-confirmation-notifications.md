# Codex 任务确认通知设计

## 目标

把 Codex 手机通知拆成三个互不混用的 ntfy 主题：

- `endpoint`：仅发送主任务最终完成通知。
- `confirmationEndpoint`：仅发送主任务等待确认、选择、授权或后续执行的通知。
- `quotaEndpoint`：仅发送额度状态与变化通知。

## 分类语义

外部 `agent-turn-complete` 事件不会区分真正完成与等待用户输入，因此分发器必须结合本轮用户任务和最终回复分类。

以下情况属于任务确认，并优先于“已经完成部分工作”等表述：

- 最终回复直接要求用户确认、选择、授权、回复关键词或提供补充信息。
- 最终回复给出下一步实施方案，同时明确尚未修改、尚未执行、只完成只读诊断或仍需继续处理。
- 已完成实现或局部工作，但仍要求用户选择合并、推送、保留分支等后续动作。
- 因缺少依赖、权限或环境而停下，并要求用户授权安装或决定下一步。

以下情况属于任务完成：

- 修改、构建、测试或交付已经完成，回复没有等待用户采取行动。
- 仅汇报结果；即使正文包含普通问句或附加建议，也没有待执行方案或用户决策。

## 通知格式

任务确认标题为 `Codex 任务待确认 · <任务名>`，正文包含项目名、任务名、任务和待确认内容；使用 `user-task-confirmation-required` 事件名、较高优先级和问号标签。

任务完成沿用 `Codex 任务已完成 · <任务名>` 与 `user-task-complete`。额度通知逻辑和状态机不做改动。

## 兼容与持久化

- ntfy 配置时若没有 `confirmationEndpoint`，自动创建随机的 `codex-confirm-<guid>` 主题。
- 现有配置迁移时增加独立确认主题，不改变任务与额度主题。
- 通知守护任务继续只修复 Codex `notify` 钩子；配置文件本身不会在重启时被覆盖。
