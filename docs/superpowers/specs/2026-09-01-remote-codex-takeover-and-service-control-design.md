# Discord 远程接管与 Windows 服务控制程序设计

历史设计与实现记录：本文属于现名“码驿 · CodexRelay”的项目，保留当时的目录、服务标识、界面名称和示例。当前安装与更新请看[入门指南](../../GETTING-STARTED.md)，更名时保留的兼容标识见 [README](../../../README.md#兼容标识)。

## 目标

在不引入“协作任务”或派生任务的前提下，让唯一授权用户在外出时可以通过 Discord 明确关闭占用任务写入权的 Codex 桌面端，再继续原任务。同时提供一个放在 Windows 桌面的原生控制程序，用四个清晰动作管理 Discord 桥接服务，并持续显示真实状态。

本次改动必须满足以下结果：

- Discord 新增 `/退出Codex`，执行任何关闭操作前先展示可能被中断的桌面任务并要求确认。
- `/继续任务` 遇到 `thread already has an active writer` 时，除安全排队外，还提供“退出 Codex 并立即继续”的清晰接管流程。
- 只关闭 Microsoft Store `OpenAI.Codex` 桌面程序的进程树，不按进程名粗暴结束所有 `codex.exe`，因此不会误杀 Discord 桥接器自己启动的 App Server。
- 桌面提供 `Codex Discord 控制台` 原生 Windows 程序，包含临时开启、临时停止、长期开启、长期停用四个按钮及自动刷新的状态。
- 用户的停用选择具有最高优先级；现有通知守护程序不得重新安装或拉起已停用的 Discord 桥接任务。

## 非目标

- 不新增 `/协作任务`，不 fork 或派生侧边栏任务。
- 不让桌面端和桥接器同时写入同一个 Codex 任务。
- 不远程启动、登录或操作 Codex 桌面界面。
- 不结束来源不明的 CLI、编辑器插件或其他 App Server；无法证明属于 `OpenAI.Codex` 桌面程序时保持排队。
- 不把控制程序扩展为通用进程管理器或通用计划任务编辑器。
- 不把 Bot Token、Webhook、用户输入或完整任务内容写入新增状态文件。

## 总体架构

实现由三个边界清晰的部分组成：

1. **Discord 接管流程**：负责命令、按钮、授权、确认时效、任务预览以及把已排队请求绑定到一次接管动作。
2. **本机控制后端**：一个只接受固定动作的 PowerShell 模块/入口，负责识别 Codex 桌面程序、生成运行任务快照、关闭桌面进程树、控制计划任务并返回 JSON 状态。
3. **Windows 控制程序**：使用本机已有的 .NET Framework 4.8 C# 编译器生成 WinForms EXE。程序只调用本机控制后端，不自行复制计划任务和进程识别逻辑。

共享控制后端是唯一可以关闭 Codex 桌面端或切换桥接运行模式的实现。Discord 和 WinForms 只是两个受限前端，避免同一规则出现两个版本。

## Discord 命令与接管流程

### `/退出Codex`

Guild Slash Command 集合从 10 个增加到 11 个，新增 `/退出Codex`，不接受路径、PID 或其他自由参数。

命令执行后先刷新本机任务索引和活动回合状态，再返回仅调用者可见的确认消息：

```text
Codex 正在运行

1. <任务名>（正在执行）
2. <任务名>（待确认）
3. <任务名>（正在执行）

强制退出可能中断以上桌面任务。
```

- 目标任务（若来自继续流程）排在第一位并标注“目标任务”。
- 只列侧边栏主任务，排除子智能体、后台回合、心跳和内部任务。
- 列表包含 `运行中` 和 `待确认`，按最近活动时间排序，最多显示 10 个；超出时显示“另有 N 个任务未列出”。
- 若检测到桌面进程但没有活动主任务，明确显示“未检测到运行中主任务”，仍要求确认。
- 若未检测到 Codex 桌面程序，直接返回“Codex 桌面端未运行”，不创建确认动作。

确认消息包含红色 `确认强制退出` 和灰色 `取消` 按钮。确认令牌是不可猜测的随机值，只保存在桥接进程内，绑定授权用户、Guild、用途、任务快照指纹和创建时间，五分钟后过期且只能消费一次。

用户点击确认时重新读取桌面进程和活动任务。若出现确认页面中没有的新活动任务，则拒绝沿用旧确认并返回包含新列表的新确认页面。任务减少或结束不阻止退出。该规则保证用户不会基于过期风险清单结束新启动的任务。

### `/继续任务` 遇到桌面占用

原有持久化语义保留：用户内容先进入统一继续队列，成功落盘后才尝试 `thread/resume`。当 App Server 明确返回 active-writer 错误时：

1. 队列项继续保持 `queued`，内容不会丢失或重复提交。
2. Ephemeral 回执说明“目标任务正被其他写入者占用，已安全排队”。
3. 若检测到 `OpenAI.Codex` 桌面程序，附上活动任务清单以及 `退出 Codex 并立即继续`、`保持排队` 两个按钮。
4. 若没有检测到 Codex 桌面程序，说明占用者可能是其他 CLI/插件，不提供强退按钮，继续按原有 30 秒周期重试。

`退出 Codex 并立即继续` 本身就是基于已展示清单的一次明确确认。点击后仍执行快照复核；若出现新任务则返回新确认页面。确认成功后关闭桌面端，轮询写入权释放，并优先重试与按钮绑定的队列项。若在限定时间内仍被占用，请求保持 `queued`，用户会收到“退出已执行，但任务仍被占用，将继续排队”的结果，不会改成失败或重复创建 turn。

`保持排队` 只关闭接管建议，不取消队列项。取消请求仍由 `/继续队列` 完成。

### 接管并发

同一时间只允许一个退出动作进入执行阶段。重复按钮、过期按钮或第二个并发接管请求返回明确状态，不重复关闭进程或重复提交队列项。

## Codex 桌面程序识别与退出

桌面程序不能通过 `codex.exe` 进程名识别，因为桌面端和桥接器都会启动同名 App Server。识别规则必须同时满足：

- 根进程为 `ChatGPT.exe`；
- 可执行文件路径位于受信任的 Microsoft Store 包目录；
- 包目录名匹配 `OpenAI.Codex_*`；
- 目标 PID 和创建时间在执行前再次核对，防止 PID 重用；
- 结束范围仅为该受信任根进程及其递归子进程。

实现先对该进程树中可关闭窗口发送正常关闭请求，等待一个短暂宽限期；仍存活时再按已验证的 PID 集合由子到父强制结束。任何路径、父子关系或创建时间验证失败都必须中止操作，不回退为“结束全部 ChatGPT/codex 进程”。

退出过程不会结束：

- `Codex Discord Bridge` 的 Node.js 进程；
- 桥接器按需启动的 `codex app-server --stdio`；
- 其他无法证明属于 `OpenAI.Codex` 桌面根进程的 CLI 或插件。

## 桥接服务控制语义

控制后端提供五个固定动作：`status`、`start-temporary`、`stop-temporary`、`enable-long-term`、`disable-long-term`。前端不得传递 Shell 片段、文件路径或任意计划任务名称。

### 临时开启

- 立即启动桥接服务。
- 不改变长期自启设置。
- 若长期自启已启用，使用现有 `Codex Discord Bridge` 计划任务启动。
- 若长期自启已停用，直接以隐藏窗口启动受控 supervisor；下一次注销或重启不会自动恢复。
- 已经运行时为幂等成功，不创建第二个实例。

### 临时停止

- 立即停止当前桥接 supervisor 及其子进程。
- 不改变长期自启设置。
- 长期自启开启时，下次 Windows 登录仍自动运行。
- 长期自启停用时，保持停用。
- 已经停止时为幂等成功。

### 长期开启

- 启用 `Codex Discord Bridge` 登录触发计划任务。
- 若当前由临时 supervisor 运行，受控地切换为计划任务托管实例，保证后续崩溃恢复有效。
- 操作完成后服务立即运行，之后每次 Windows 登录自动运行。

### 长期停用

- 禁用 `Codex Discord Bridge` 计划任务并停止当前实例。
- 之后登录 Windows 不自动运行。
- 不删除 Token、配置、队列、索引或通知历史，重新开启后可恢复。

现有 `Codex ntfy Notification Guard` 只保留通知配置修复职责，删除其“桥接任务缺失就重装、未运行就启动”的耦合逻辑。桥接任务自身已有单实例 mutex、子进程重启循环和计划任务重启策略，不需要通知守护程序越权恢复。

## 运行状态与状态文件

`start-discord-bridge.ps1` 维护最小运行身份文件，包含 supervisor PID、进程创建时间、启动模式和工具目录标识；退出时尽力清理。停止操作必须把该文件与实际 Win32 进程信息交叉验证，不能只信任 PID 文件。

桥接器维护一个不含秘密的健康快照，至少包含：

- Gateway：连接中、已连接、已断开或故障；
- REST 最近一次成功/失败时间；
- 桥接启动时间和最近心跳；
- 继续队列数量；
- 最近一次脱敏事件类别。

写入采用临时文件加原子替换。状态读取失败只显示“未知”，不能导致控制按钮失效，也不能根据损坏状态猜测停止任意进程。

## Windows 控制程序

控制程序采用 C# WinForms，目标为本机已有的 .NET Framework 4.8，由仓库中的构建脚本调用系统 `csc.exe` 生成 Windows GUI EXE，不要求安装 .NET SDK、Electron 或新的包管理依赖。

正式 EXE 部署到 `mobile-notify` 工具目录，桌面创建名为 `Codex Discord 控制台` 的快捷方式。这样升级只替换受控工具目录中的程序，不会让桌面残留旧二进制。

主窗口包含：

- `桥接服务`：运行中、已停止、启动中、异常或未知；
- `开机自启`：已开启或已停用（实际为当前用户登录触发）；
- `Discord`：已连接、连接中、已断开、故障或未知；
- `Codex 桌面端`：运行中或未运行；
- `继续队列`：当前条数；
- `最后活动`：本地时间；
- 四个主按钮：`临时开启`、`临时停止`、`长期开启`、`长期停用`；
- 一个手动刷新入口和简短结果/错误栏。

窗口每两秒异步刷新，不阻塞按钮。动作执行期间禁用四个动作按钮，完成后立即刷新。破坏性较高的 `长期停用` 需要本地确认对话框；其他动作直接执行并展示结果。控制程序不显示或读取 Discord Token。

## 错误处理

- Discord 授权、Guild 或确认令牌校验失败：拒绝操作且不泄露本机状态。
- 任务索引刷新失败：仍可报告 Codex 是否运行，但退出确认显示“任务清单不可用”；此时拒绝远程强退，避免在风险未知时操作。
- 桌面进程在确认前自行退出：视为幂等成功，并继续重试绑定队列项。
- 正常关闭超时：仅对已验证进程树执行强制结束。
- 退出后仍返回 active-writer：保留队列并提示可能由其他 CLI/插件占用。
- 计划任务不存在：状态显示“未安装”；临时动作不得静默注册。长期开启可调用既有安装定义重建任务，但必须使用仓库固定任务名和脚本路径。
- 控制动作部分失败：返回实际的运行状态与自启状态，不使用模糊的“成功”。

## 安全与隐私

- 沿用唯一 Guild 和唯一 Discord 用户双重授权。
- 所有 Discord 回执均为 Ephemeral，并禁用 mentions。
- 自定义按钮 ID 只包含随机引用，不包含任务内容、PID 或本机路径。
- PowerShell 控制后端只接受枚举动作；路径、任务名和进程选择由程序内部固定产生。
- 新增日志只记录动作类别、成功/失败、短 ID 和耗时，不记录 Token、完整任务名、用户文本或完整路径。
- 配置、DPAPI Token、运行身份和健康快照继续排除在版本控制之外。

## 部署与回滚

部署流程先备份 live `mobile-notify`，再复制源文件、构建控制程序、更新 Guild 命令、重启桥接任务并创建/更新桌面快捷方式。不能用仓库示例覆盖 live `config.json`、DPAPI Token 或状态文件。

回滚恢复备份文件并重新注册旧的 10 条命令。控制程序快捷方式和 EXE 可以删除；计划任务恢复到部署前设置。若新版已执行“长期停用”，回滚不得擅自重新启用服务，必须保留用户当前选择。

## 测试策略

### Node.js 单元测试

- Guild 命令完整集合为 11 条且包含 `/退出Codex`。
- 未授权用户、错误 Guild、过期/重复/不匹配的确认令牌均不能执行。
- 任务预览只含主任务，排序、目标标记、10 条上限和剩余计数正确。
- active-writer 路径先持久化队列，再生成接管建议。
- 保持排队不取消请求；确认退出只优先重试绑定项。
- 新任务出现时旧快照失效并要求重新确认。
- 非桌面占用者不出现强退按钮。

### PowerShell 测试

- 用合成进程对象验证 `OpenAI.Codex` 根进程识别、路径白名单、PID 创建时间和递归子进程边界。
- 验证任何模糊或错误路径都拒绝结束，不回退为名称匹配。
- 验证四种服务动作的幂等性以及“临时动作不改变长期设置”。
- 验证长期启用时临时 supervisor 能切换到计划任务托管。
- 验证通知守护程序不再安装或启动 Discord 桥接任务。
- 验证损坏/陈旧运行身份文件不会导致停止无关进程。

### 控制程序和集成测试

- 编译 WinForms EXE，并以无界面的状态探针入口验证状态模型和控制后端 JSON 兼容性。
- 验证桌面快捷方式目标指向 live 工具目录中的当前 EXE。
- 完整 Node、PowerShell、语法、仓库卫生和 `git diff --check` 测试通过。
- 部署后只做非破坏性 live 检查：11 条命令注册成功、Gateway 已连接、控制程序状态可读、四按钮状态与计划任务一致。
- 自动化和部署验证不得真实关闭当前 Codex 桌面端；结束行为使用测试替身。真实退出由用户首次从 Discord 主动确认时验证。

## 验收标准

- 用户在外面执行 `/继续任务` 遇到桌面占用时，明确看到已排队、正在运行的任务清单和接管选项。
- 未经确认不会退出 Codex；清单变化时不会沿用旧确认。
- 确认后只退出 `OpenAI.Codex` 桌面端，桥接器保持在线并优先继续目标请求。
- 桌面控制程序可直接打开，状态自动更新，四个按钮符合约定语义。
- 临时停止不会被通知守护程序立即拉起；长期开启/停用在下一次 Windows 登录后仍生效。
- 关闭、重启、CC Switch 和桥接器崩溃不会覆盖用户的长期启用选择，也不会泄露私密配置。
